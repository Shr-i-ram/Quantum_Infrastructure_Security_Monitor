## 1. Overview of Verification Framework

To satisfy the non-negotiable scientific requirement **"Never Fabricate Evidence"** and guarantee that every statement defended before a technical review panel is grounded in verifiable project artifacts, this document maps every primary scientific and quantitative claim directly to:
1. Exact source code files and class/function identifiers.
2. Saved model checkpoints and preprocessor artifacts.
3. Raw JSON, CSV, and Markdown benchmark reports.
4. Generated visualization plots and dashboards.
5. Unit and regression test implementations.
6. Empirical verification status (`VERIFIED`, `POTENTIAL CONCERN`, `UNPROVEN / NOT RECOVERABLE`).

## 3. Potential Data Leakage & Methodological Audit Matrix

| Potential Leakage Source | Actual Risk Level | Evidence Examined | Audit Status | Consequence for Reported Results |
|---|---|---|:---:|---|
| **Ground-Truth Label Leakage in Features** | High if unmitigated | `src/qism/telemetry/features.py`, `src/qism/ml/features/definitions.py`, `src/qism/monitor/ingestion.py` | **VERIFIED SAFE** | Ingestion layer explicitly scans against `FORBIDDEN_GROUND_TRUTH_KEYS` and routes ground truth strictly to metadata sidecars. | **Future Lookahead in Streaming Inference** | High if unmitigated | `src/qism/temporal/windowing.py`, `src/qism/temporal/streaming.py`, `src/qism/monitor/orchestrator.py` | **VERIFIED SAFE** | Causal circular buffers ($W_t = [X_{t-L+1}, \dots, X_t]$) enforce unidirectional time flow. | **Scenario Boundary Crossing in Slicing** | Moderate | `src/qism/ml/models/temporal.py` (V0.6) vs `src/qism/temporal/windowing.py` (V0.7+) | **REPAIRED IN V0.7** | In V0.6, sequence creation naively sliced contiguous arrays across concatenated scenarios. V0.7 introduced strict `("scenario_id", "run_id")` trajectory barriers. V0.6 temporal metrics were slightly contaminated; V0.7–V1.0 are leak-free. |
| **Cross-Scenario Run ID Group Collision** | Moderate | `src/qism/ml/features/extractor.py` (V0.6) vs `src/qism/temporal/windowing.py` (V0.7+) | **REPAIRED IN V0.7** | V0.6 grouped by `run_id` only, causing collisions across scenarios sharing `"run_0000"`. V0.7 enforced composite tuple grouping `("scenario_id", "run_id")`. Fixed in all subsequent versions. |
| **Validation Contamination in Test Set** | Moderate | `src/qism/ml/data/splits.py` (V0.6) | **CONFIRMED IN V0.6 / ISOLATED IN V0.7+** | V0.6 `SplitManager` placed `val_normal` directly into `test` partition (`by_split["attack"] + val_normal`), causing threshold calibration samples to be scored as evaluation test data. V0.7+ disentangled calibration partitions. |
| **Preprocessing Fit on Test / OOD Data** | High if unmitigated | `src/qism/ml/preprocessing/scalers.py`, `src/qism/monitor/orchestrator.py` | **VERIFIED SAFE** | Preprocessing scalers (Standard/Robust) are fit strictly on unperturbed nominal baseline calibration data (`make_nominal_baseline_matrix`). | **Adversarial Contamination of Adaptation Reference** | Critical in online learning | `src/qism/drift/adaptation.py`, `src/qism/drift/reference.py` | **VERIFIED SAFE** | Safe adaptation state machine locks reference accumulation when anomaly score ratio exceeds 0.80 or active alarms exist.
