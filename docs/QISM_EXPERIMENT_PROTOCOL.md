# Quantum Infrastructure Security Monitor (QISM)
## Experimental Protocol and Leakage Governance

This document establishes the experimental protocol, data partitioning rules, preprocessing policies, threshold calibration procedures, and leakage prevention mechanisms governing the QISM model benchmark.

---

## 1. Experimental Populations and Partitions

The benchmark uses the authoritative research dataset generated by the QISM simulator (`data/qism_research_dataset`), consisting of **10,100 telemetry windows**, **10.1M physical optical pulses**, **200 scenarios**, and **505 independent simulation runs** across six partitions:

```
data/qism_research_dataset/
├── calibration/              (40 runs, 800 windows, nominal reference)
├── train/                    (180 runs, 3,600 windows, 100% normal)
├── validation/               (50 runs, 1,000 windows: 826 normal, 174 attack)
├── test_in_distribution/     (135 runs, 2,700 windows: 1,866 normal, 834 attack)
├── test_generalization/      (50 runs, 1,000 windows: 688 normal, 312 attack)
└── test_stress/              (50 runs, 1,000 windows: 740 normal, 260 attack)
```

### Partition Roles:
1. **`train` (Normal-Only Training Pool)**: Strictly normal operating conditions ($0\%$ attack pulses). Used exclusively to fit all data scalers, imputation medians, PCA projection matrices, and to train all one-class and unsupervised anomaly detectors.
2. **`validation` (Tuning and Threshold Calibration)**: Independent scenarios with both normal and attack episodes. Used strictly for hyperparameter validation and decision threshold calibration ($\alpha = 0.01$ and $0.05$ target FPR). Never used for training model parameters.
3. **`test_in_distribution` (Primary Test Set)**: Completely held-out simulation runs and scenarios covering all six supported attack families (Intercept-Resend, Photon-Number Splitting, Source Manipulation, Channel Loss, Detector Manipulation, Timing Delay).
4. **`test_generalization` (Out-of-Distribution Physics)**: Held-out physical transmission regimes with extended distances ($50.0 - 75.0$ km) and low detector efficiencies ($\eta \in [0.30, 0.42]$) never seen during training.
5. **`test_stress` (Extreme Environmental Fluctuations)**: Operational stress scenarios with extreme loss drift, ambient background light spikes, and severe temperature fluctuations.
6. **`calibration`**: Attack-free baseline runs used for reference calibration and sensor baseline normalization.

## 2. Non-Negotiable Leakage Safeguards

### 2.1 Explicit Input Feature Allowlist
Only 76 observable physical telemetry features are permitted as model inputs. The model input vector $x_t \in \mathbb{R}^{76}$ contains:
- Sifted counts, gains, rates, and quantum bit error rates ($Q_{\mathrm{obs}}$, $Q_Z$, $Q_X$, $R_{\mathrm{sift}}$, $\Delta_c$, $R_{\mathrm{double}}$).
- Detector dynamics (counts, dark clicks, dead-time losses, interarrival moments, kurtosis, skewness, candidate rates).
- Optical pulse statistics (mean photon number, variance, vacuum/single/multiphoton fractions).
- Physical channel estimates (estimated loss in dB, transmittance variance and drift).
- Environmental monitoring sensors (sensor temperatures, ambient background light drift, vibrations, clock drift).

### 2.2 Excluded Metadata and Labels
The following attributes are strictly banned from model inputs and are extracted exclusively as evaluation targets or provenance metadata:
- `ground_truth_attack_active` (0 or 1)
- `ground_truth_attack_type` (attack family name)
- `ground_truth_attack_phase` (onset, sustained, decay)
- `ground_truth_attack_fraction`
- `ground_truth_mean_severity`
- `ground_truth_attack_id`
- `scenario_id`, `run_id`, `window_id`

### 2.3 Preprocessing Isolation
All feature transformations are fitted **strictly on `train`** and frozen:
- **Median Imputation**: Computed on normal training data. All-NaN columns (e.g. unconfigured decoy residuals) are safely initialized to 0.0.
- **Standardization**: Mean $\mu_{\mathrm{train}}$ and standard deviation $\sigma_{\mathrm{train}}$ are computed on `train`.
- **Principal Component Analysis (PCA)**: Eigenvectors $V \in \mathbb{R}^{76 \times k}$ are computed on $X_{\mathrm{train}}$.
- **Quantum Angle Scaling**: Feature ranges $[0, \pi]$ are mapped using training minimum and maximum values.

## 3. Training Protocols by Learning Paradigm

### 3.1 Unsupervised and One-Class Protocol
Applicable to: *Isolation Forest, One-Class SVM, Local Outlier Factor, Mahalanobis Distance, Robust Covariance, Classical Autoencoder, Temporal Autoencoder, Classical Deep SVDD, Quantum Autoencoder, Static Quantum SVDD, and Flagship PI-TQSVDD*.
- **Training Data**: 3,600 normal windows from `train` only.
- **Attack Labels**: Zero access during training.
- **Threshold Calibration**: The decision threshold $\tau$ is determined using normal validation scores:
  $$\tau_{1\%} = \mathrm{Percentile}\left(\{s(x) \mid x \in \mathcal{D}_{\mathrm{val}}, y=0\}, 99.0\right)$$
  $$\tau_{5\%} = \mathrm{Percentile}\left(\{s(x) \mid x \in \mathcal{D}_{\mathrm{val}}, y=0\}, 95.0\right)$$
- **Test Evaluation**: Applied to test sets without any threshold adjustments based on test labels.

### 3.2 Supervised Baseline Protocol
Applicable to: *Classical Logistic Regression, Random Forest, Small Classical MLP, Classical RBF-SVM, and Variational Quantum Classifier (VQC)*.
- **Training Data**: Labeled development split composed of 500 normal windows from `train` and validation attack windows from `validation`.
- **Test Integrity**: Test partitions (`test_in_distribution`, `test_generalization`, `test_stress`) remain strictly pristine and held-out.

---

## 4. Causal Temporal Sequence Protocol

For all sequence and temporal models (Classical Temporal Autoencoder, PI-TQSVDD):
1. **Sequence Length**: Fixed window length $L = 3$ consecutive telemetry steps (each window represents 1,000 optical pulses at 1 MHz, corresponding to 1 ms physical duration).
2. **Scenario Isolation**: Sliding windows are constructed strictly within individual scenario runs. No window ever spans across different simulation runs or scenarios.
3. **Causality**: At time step $t$, the input tensor is $X_t = [x_{t-2}, x_{t-1}, x_t]$. Future information is strictly inaccessible.
4. **Temporal Target**: For dynamical prediction objectives, the target is $x_{t+1}$. If $t+1$ exceeds the scenario boundary, the step is flagged with `has_target = False` and excluded from prediction loss.

---

## 5. Event-Level Operational Metrics

To prevent false overcounting of prolonged attack episodes as thousands of independent events:
- **Incident Recall**: Fraction of distinct attack injection episodes detected (at least one alarm raised between attack onset and offset).
- **Detection Delay**: Number of telemetry windows elapsed between attack start and the first alarm:
  $$\Delta t_{\mathrm{detect}} = t_{\mathrm{first\_alarm}} - t_{\mathrm{attack\_onset}}$$
- **False Alarm Rate (FAR)**: Number of false alarms divided by total benign normal operating windows during uncompromised operation.
